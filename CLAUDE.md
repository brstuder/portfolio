# Project Conventions

MkDocs Material portfolio site.

## Architecture diagrams

Diagrams are generated by the `architecture-diagram` skill in
`.claude/skills/architecture-diagram/`. Read `SKILL.md` before creating or
editing one.

- **Source:** `diagrams/src/*.svg` — readable, hand-authored.
- **Output:** `docs/images/diagrams/*.svg` — generated, font embedded.
- **Inbox:** `diagrams/inbox/` — drop a reference mockup (PNG only — not an Excalidraw SVG
  export, which is expensive to read) here to build from it instead of a text description.
  See `SKILL.md` → "Working from a Reference Mockup". Delete the mockup only after the
  user confirms, never automatically.

Build:

```bash
python3 .claude/skills/architecture-diagram/resources/build.py diagrams/src/NAME.svg
```

Rules:

- **Never hand-edit `docs/images/diagrams/`.** It is build output. Edit the
  source and rebuild.
- **Commit both** source and output. `mkdocs gh-deploy` does not run the build.
- Reference diagrams as `![Alt](../images/diagrams/NAME.svg){: .dia-dark }`.
  The `.dia-dark` class drives light/dark inversion and is required.
- **Do not modify `docs/stylesheets/style.css`.** The inversion rules there are
  the contract the diagram pipeline is built around.
- **Do not inline diagram SVGs into page HTML** — no inline-svg plugin, no
  `pymdownx.snippets` include, no custom hook. Inlining removes the `<img>`
  element, so `img.dia-dark` stops matching and light/dark silently breaks.
- Built SVGs must contain **zero external references**. Only `url(#...)`
  fragments and `url(data:...)` are permitted.

## Fonts

Diagrams self-host Inter (`docs/assets/fonts/inter-latin-*-normal.woff2`),
embedded and subset per-diagram by `build.py`. This is separate from the
site's body font (Lato, via Google Fonts in `mkdocs.yml`) — Inter is used for
diagram legibility only. Paths are configured in `CONFIG` at the top of
`build.py`; after changing them, re-run `make_metrics.py`.
